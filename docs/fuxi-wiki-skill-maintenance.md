## 上游更新流程

每次准备升级 Hermes 前执行：

```sh
git fetch upstream main
node scripts/check-fuxi-wiki-upstream.mjs --ref upstream/main
```

脚本比较整个上游技能目录的 Git 树，包括未来新增的脚本与参考文件，不只比较版本号。
退出码 0 表示内容已经审阅；2 表示有新变化必须分析；1 表示读取失败，不能按无变化处理。
默认检查 HEAD，用于合并上游后的持续集成。脚本只读，不调用模型、不合并、不覆盖中文文件。

出现新变化时，以 `scripts/fuxi-wiki-upstream.json` 的上次已审阅提交为基线执行：

```sh
git diff 已审阅提交 upstream/main -- skills/research/llm-wiki
```

维护者逐项决定合并、中文改写或不采纳，并记录原因；适用的行为变化融入中文技能相应章节。
完成测试后才把审阅提交、目录树指纹与决定追加进审阅记录。不能只更新指纹消除报警。
整个 Hermes 版本变了但技能目录未变时，不需要为此重写技能。上游不得自动覆盖改造版。
