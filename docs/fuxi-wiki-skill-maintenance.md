## 上游更新流程

每次准备升级 Hermes 前执行：

```sh
git fetch upstream main
node scripts/check-fuxi-wiki-upstream.mjs --ref upstream/main
```

脚本比较整个上游技能目录的 Git 树，包括未来新增的脚本与参考文件，不只比较版本号。
退出码 0 表示内容已经审阅；2 表示有新变化必须分析；1 表示读取失败，不能按无变化处理。
默认检查 HEAD，用于合并上游后的持续集成。脚本只读，不调用模型、不合并、不覆盖中文文件。

出现新变化时，以 `scripts/fuxi-wiki-upstream.json` 的上次已审阅提交为基线执行：

```sh
git diff 已审阅提交 upstream/main -- skills/research/llm-wiki
```

维护者逐项决定合并、中文改写或不采纳，并记录原因；适用的行为变化融入中文技能相应章节。
完成测试后才把审阅提交、目录树指纹与决定追加进审阅记录。不能只更新指纹消除报警。
整个 Hermes 版本变了但技能目录未变时，不需要为此重写技能。上游不得自动覆盖改造版。

## 用户核验清单

2026-09-13：版本 1.0.3 区分已修改页面的最小回执与无需修改时的完整审阅回执。真实任务在296.6秒才写完回执、300秒超时；已修改页面却重复序列化事实集合属于多余输出。新增两类中文JSON示例和CI合同测试，未修改原生上游技能、引擎、权限、预算、发布校验或生产文件。示例测试只证明合同说明一致，不证明模型必然遵循，也不宣称真实费用或超时已解决。不得将失败任务强行恢复为成功。

1. 文档：直接阅读中文技能，确认知识组织、修改范围和续做动作由 Hermes 决定。
2. 加载：在隔离 profile 用原生技能发现与加载入口读取 `llm-wiki-fuxi`，确认内容哈希与仓库一致；缺文件不能回退外部 policy。
3. 运行：一次正常摄入中不追加 Codex 指令；中断后的授权续接使用真实草稿和进度，不重新处理已完成来源。
4. 业务：完整清单逐项对应；冲突列出双方来源；同义主题无无意义重复；中文实体、概念与索引可用；全库校验通过后原子发布。
5. 成本：新增来源不无差别重读全部旧正文，记录实际模型调用和输入输出用量；只测文件大小不能声称费用下降。

文档与只读更新检查通过不代表第 3 至 5 项通过。技能不能单靠文字实现请求暂停、会话持久化或调度；这些基础能力必须在运行系统实际接通，但不得替技能做语义决策。
2026-09-10 评审整改：版本 1.0.1 消除历史来源边界冲突，增加信任与撤回边界，中文示例随 `references/chinese-examples.md` 分发。公开日志与内部进度分离；Skill 不虚构暂停接口。

## 原生会话续接验证（2026-09-10）

带认证的 Chat Completions 会话复用现有 `SessionDB.get_compression_tip`，读取压缩后的最新历史；
原生分支、工具子会话不作为压缩续接。数据库或历史读取失败返回503，不再静默清空历史后调用模型。
新会话仍可创建；没有 session header 的无状态入口不改变。

`python tests/gateway/test_native_chat_resume_offline.py` 使用真实本地HTTP与临时SQLite，
仅模型入口替换成合成适配器。覆盖数据库重开、压缩恢复、分支隔离、认证和读取失败，
并证明两个合成回合中的四次供应商请求及token分别累计。该数据不是账单，也不证明费用下降。
运行环境需已有aiohttp等Hermes运行依赖；可在既有镜像中只读挂载本仓库运行，禁网、不重建镜像。

稳定会话是基础能力，不自动重试失败任务，不构成后台调度的让出协议，也不代替Skill决定下一步。
FUXI业务验收仍须另验证未完成单元进度、预算边界与无人工追加指令的完整任务。
