# 链接拒绝后的实际纠错

以下是合成示例，只说明原生文件工具与既有来源合同，不决定客户的主题、实体或页面。

## 先区分读取证据与发布导航

假设当前阅读目录明确声明：

- `RAW: raw/sheet-2/cells-001.md` 是可读的单元格证据，不是可见 Wiki 页面。
- `PUBLISHED_SOURCE: raw/material-a.md` 是同一来源的可见包装页。
- 原始坐标是 `sheet-2 / B6`；不得因修改链接而改掉坐标或内部事实引用。

可读路径存在不证明它可作导航目标。下面的链接仍然指向错误目标，改别名不会修复它：

```markdown
[[raw/sheet-2/cells-001.md|中文来源]]
```

核实真实对应关系后，使用已声明的发布来源；坐标在正文独立保留。没有可验证的对应关系就报告具体缺口，不能任意挑一个允许路径。

## 用原生局部补丁验证正文真的改变

先用 `read_file` 读取实际文件。原文必须唯一；下面的两次合成操作保留业务内容与坐标，只改变错误导航。每次等待实际工具结果，不能因为“我已修复”的说明就认定成功：

```json
{"tool":"write_file","path":"concepts/example.md","content":"# 合成主题\n\n工作表 sheet-2，坐标 B6。\n\n[[raw/sheet-2/cells-001.md|中文来源]]\n"}
```

```json
{"tool":"patch","path":"concepts/example.md","old_string":"[[raw/sheet-2/cells-001.md|中文来源]]","new_string":"[[raw/material-a.md|中文原始资料]]"}
```

示例第一步只在隔离材料中构造错误稿；生产工具已拒绝的内容不在磁盘上，必须基于实际读回的原文构造补丁。不要对不存在的错误稿盲目补丁，也不要重复发送被明确拒绝的同一正文。

若表格中的链接转义导致目标不正确，可以在表格中保留纯文本坐标，在表格外维护已核实的来源链接。不要用反斜杠、改扩展名或换别名掩盖错误目标。

修正后核对诊断目标已从候选正文消失、对应发布来源存在、原坐标与业务要求没有丢失，再提交。仍有新错误就处理新的具体诊断，不能原样重复失败稿。发布检查独立保留，示例正确不代表整库已经通过。
