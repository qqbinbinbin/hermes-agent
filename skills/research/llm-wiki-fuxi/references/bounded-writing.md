# 长页面的局部写入

这些合成例子只示范工具使用，不规定客户页面主题。路径必须替换为当前授权路径。
已有页面不能执行第一步覆盖；先读实际目标段落，再执行局部补丁。

新页先保存已核实内容，之后保留唯一的末段上下文，加入下一段。下面两次调用完成同一个页面：

```json
{"tool":"write_file","path":"concepts/example.md","content":"---\ntitle: 合成清单示例\ntype: concept\n---\n# 合成清单示例\n\n## 已核实项目\n- 项目甲：合成出处甲。\n"}
```

```json
{"tool":"patch","mode":"replace","path":"concepts/example.md","old_string":"- 项目甲：合成出处甲。\n","new_string":"- 项目甲：合成出处甲。\n- 项目乙：合成出处乙。\n"}
```

后续以实际成功保存的末段为上下文继续。同名或重复行不能单独作锚点，应包含附近的唯一章节或多行内容。不得使用 `replace_all` 追加清单。

返回不确定时，先用 `read_file` 读取相应位置；返回有分页则按真实偏移续读。若项目乙已经存在且内容一致，不再提交同一追加。若不一致或补丁找不到上下文，读取实际段落后重新形成局部修改，不重放旧参数。

每批成功后核对清单边界与出处；完整页最终必须包含全部项目，不以本例的两项或单次建议字符数作为完整性标准。跨回合待续使用任务已有内部进度接口，不向用户日志写技术恢复信息。
