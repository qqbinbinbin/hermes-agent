# 真实进度的保存与续做

工具结果中的 `fuxiContinuation` 是运行系统提供的预算与文件许可信息，不是知识内容。`remainingRequests` 是本回合还可进入的原生模型循环步骤数，不包括供应商内部重试，不是计费请求数、剩余文件数、总任务时长或可增加的额度。页面主题、未完成事项和下一步仍由你决定。

如果还有未解决内容，使用单独一次 `write_file` 写入通知中的 `progressPath`，其 `content` 为下面这种完整 JSON。三个身份字段逐字取自通知的 `identity`，不能照抄示例值；路径使用真实已成功保存或已核查的非空文件授权绝对路径。下面只演示格式，不代表任何客户事实。

```json
{
  "version": "kb-wiki-unit-progress-v1",
  "unitId": "取自本轮 identity.unitId",
  "turnNonce": "取自本轮 identity.turnNonce",
  "batchInputHash": "取自本轮 identity.batchInputHash",
  "summary": "已经核对并保存的实际工作。",
  "remaining": "尚未核对的具体内容与未解决诊断。",
  "nextAction": "由你决定的下一项具体核对或编辑动作。",
  "savedPaths": [],
  "readPaths": ["/本轮授权根目录/实际已经核查的非空文件.md"]
}
```

只有实际保存成功才算持久化待续；工具拒绝时用剩余请求自行按诊断修正。保存成功后结束本回合，不另写完成回执，不把它加入索引、日志或发布文件。若已经真正完整完成，仍提交实际完成回执，不能为凑预算制造待续。

下一次合法续接核对文件现状与进度再继续；同一作业的预算、权限和费用累计保持。支持可靠原生暂停时，运行时也可保存并核验真实对话和工具结果，再在原任务剩余额度内恢复同一会话；它不是平台编写的语义进度，不增加业务完成数。没有得到原生保存确认或合法进度回执时，不从最后文字补写，不自动重开模型。失败、取消和整项预算耗尽不是正常暂停，不能恢复为进行中。保存进度不是内容验收，也不是新增授权。
